# RDC / GPTAdmin Wake v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make new-chat binding and continuation re-entry work through canonical `RDC -> GPTAdmin -> development-bridge` without depending on the direct `Dev_Bridge` namespace.

**Architecture:** Reuse the existing RouteRegistry bind candidate/commit state machine. Add a safe MCP prepare tool for hub ingress, a dedicated authenticated browser-binder HTTP API, and a small WebExtension that supplies the current ChatGPT tab out of band. Keep ReviewGPT as the only primary direct wake transport.

**Tech Stack:** Python 3.12, Starlette, Pydantic, pytest, existing RouteControlService/RouteRegistry, Firefox/Chromium WebExtension APIs, ReviewGPT.

**Spec:** `docs/superpowers/specs/2026-09-14-rdc-wake-v2-design.md`

## Global Constraints

- Never place physical ChatGPT target data or bind credentials in model-visible MCP content.
- Do not create a second continuation queue or wake state machine.
- Preserve existing generation, project-policy, expiry, replay, and uncertain-no-resend semantics.
- Keep the current direct MCP App bind flow working for compatibility.
- Binder authorization is dedicated and cannot authorize ordinary Bridge operations.
